GKE Reporting & Correlation Engine

A Python runbook companion that brings together cluster metrics, Cloud Monitoring alerts, Cloud Logging evidence, and pod failure signals. It groups nearby evidence, prepares a rule-based RCA summary, and can notify the team.

Overview

A single evidence packet for cluster triage

The engine reads from Google Cloud APIs and a Monarch-backed Prometheus query endpoint, then turns the results into a timestamped incident report.

Run on demand or schedule

Purpose: shorten first-pass investigation by collecting signals for one configured GKE cluster and time window, correlating them by time, and surfacing actionable evidence with likely causes.

What it produces

Each run saves a machine-readable JSON report and a Markdown handoff summary.

  • Correlated incident groups and shared labels
  • Ranked RCA hypotheses with evidence
  • Collection errors and notification delivery status

Use case / problem statement

Incident clues are scattered across tools

During a Kubernetes incident, engineers often need to switch between dashboards, alert pages, and logs before a shared timeline is visible.

Operational pain point
Design boundary: RCA is a ranked, explainable hypothesis based on matching rules and time proximity. It helps direct investigation; it does not prove causation or remediate the cluster.

Architecture

Four evidence sources, one reporting engine

Monarch is accessed through the documented Managed Service for Prometheus query API. Cloud Monitoring and Cloud Logging provide alert and log records.

ADC Â· read-only APIs

The script does not call an undocumented Monarch endpoint. It uses Google Cloud APIs with Application Default Credentials and read scopes.

Automation flow

From YAML inputs to an incident handoff

A run is bounded by the configured lookback and correlation windows. Failures in one source are recorded so available evidence can still be reported.

Pod failure coverage

Failures are surfaced as actionable evidence

PromQL checks look for kube-state-metrics series. The log classifier recognizes common reasons and explicit exit-code phrases when they appear in collected log messages.
